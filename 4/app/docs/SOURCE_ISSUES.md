# Проблемы источника

## SRC_NWC — PDF 8,13

Стр.8 ΔNWC назван оттоком −4 млн; стр.13 ΔNWC вычитается из FCFF.

Решение: NWC_change=+4 млн при вложении, −4 млн при возврате; cash_effect=−change. Ни CAPEX, ни NWC не облагаются WHT.

Проверка: test_calendar; test_identities.

## SRC_WHT — PDF 13

Текст требует WHT с положительного операционного CF; печатная ветвь: FCFF−ΔNWC*(1−WHT) при FCFF≤0, FCFF−ΔNWC при FCFF>0.

Решение: Основной economic_rule; буквальный literal_pdf NON_AUTHORITATIVE сохранен точно по визуально проверенной типографике. Не добавлены отсутствующие скобки вокруг FCFF−ΔNWC.

Проверка: test_wht; test_literal_pdf_exact_typography.

## SRC_NEG_TAX — PDF 13

max(CIT_gross, EBIT*floor) при EBIT<0 может создавать налоговый возврат.

Решение: Основной cash_tax=max(0,literal_tax), без переноса убытков. Буквальная формула сохранена отдельно; численный эффект публикуется.

Проверка: test_cash_tax.

## SRC_VNM_TAX — PDF 5,14

База VNM 15% t3–11,20% t12–13; edge case требует 0%→15% в первые 4 года.

Решение: Базовый календарь сохраняется; отдельная фикстура PILLAR2 задает 0% t3–6 и проверяет пол при положительном EBIT.

Проверка: test_tax_calendar_and_credit; test_scenarios.

## SRC_SRB_IP — PDF 5,14

3% IP Box относится к роялти, которых у проекта нет.

Решение: Налог SRB 15% в базе и стрессе; отмена IP Box не создает искусственного налогового эффекта.

Проверка: test_scenarios.

## SRC_EXPORT — PDF 2,10

На стр.2 указано 85% экспорта; таблица2 задает полное распределение продукции по рынкам ЕС/Азии.

Решение: Для денежной модели приоритет конкретной матрице рынков. Отдельный неназванный внутренний рынок 15% не добавляется.

Проверка: test_pdf_controls.

## SRC_DEU_CIT — PDF 5

29.80% в строке DEU отличается от суммы перечисленных компонентов 15+0.825+14=29.825%.

Решение: Применяется явно заданная сводная ставка 29.80%; компоненты остаются в оригинальном тексте CSV.

Проверка: test_pdf_controls.

## SRC_SUBSIDY_TIME — PDF 7,8,12

DEU субсидия t4 описана как через год после ввода t3; первый полный CF по календарю t4.

Решение: Не смешивать ввод в конце t3 с потоком t4; t_subsidy=4 считывается отдельно, субсидия учтена только в CF0 через PV.

Проверка: test_capex_exemption_and_advance.

# Отображение содержания на пользовательский шаблон

Шаблон: `data/report_template.docx` (контрольная копия пользовательского DOCX; SHA256 в manifest). Исходный файл в `lectuion` не изменяется.

| Глава шаблона | Содержание и источник |
|---|---|
| Титул | Сохранены XML титульного блока и таблица исполнителей; заполнены №4, тема PFSA/PEM, объект, год; персональные сведения не выдумываются |
| 1. Цель и задачи | Цель выбора DEU/SRB/VNM по Parent NPV и задачи верификации |
| 2. Объект | Подтвержденное описание технологии и масштаб из входных DTO |
| 3. Исходные данные | Источники/SHA256, таблица «база / сценарий2», контроль входа; сценарий2=В «Фрагментация» |
| 4. Архитектура | Таблица этап/поток/назначение и распределение ответственности |
| 5. Методика | Подразделы5.1/5.2; все формулы реестра Cambria Math12 с единицами, определениями переменных и источниками |
| 6. Результаты | Сводная таблица метрика/значение/единица/статус; блоки03–11: риски, CAPEX, логистика, календарь, CF, DPP, налоги, метрики, Excel |
| 7. Harness Log | Карточка поле/содержание для каждого фактического дефекта, причины/исправления/повторная проверка; блок20 |
| 8. Тестирование и сценарии | Фактический протокол тестов; блоки12–15, оба стресса, абсолютные/относительные изменения, A/Б/В, ожидание и дисперсия |
| 9. Визуализация | Блок17 с реальным графиком чувствительности; реестр всех13 рисунков, ссылки на CSV и контроль просмотра |
| 10. Допущения и качество |10.1 таблица код/допущение/обоснование/влияние;10.2 Data Quality Report; блоки16/18 с аудитом WHT/NWC и источника |
| 11. Анализ и ограничения | Блок19: причинные связи, инвестиционный вердикт, границы применимости |
| 12. Итоговые выводы | Численные выводы из тех же расчетных DTO и фактические статусы проверок |
| Приложения | Полные годовые блоки по странам, все входные параметры, команда воспроизведения и метаданные запуска |

Раздел13 исходного файла содержит правила заполнения. Эти правила применяются к документу, а служебный раздел и все квадратные заполнители исключаются из сдаваемого отчета.

Рисунки расположены сразу после связанных таблиц; перед рисунком есть ссылка в тексте, под ним подпись и непосредственный анализ. Отдельного оторванного атласа нет. Все исходные ReportSectionDTO включаются ровно один раз; это проверяется автоматически.

Оформление проверяется тестами и TemplateReportValidationService: TNR12/1.15/отступ1.25см; заголовкиTNR15/13 #1F4E78; Table Grid и синие шапки; формулы Cambria Math12 по центру; A4/поля наследуются из шаблона. Word theme-font attributes удаляются из изменяемых стилей, чтобы тема не подменяла заданный шрифт. Существующее поле PAGE сохраняется без дублирования.

В шаблоне обнаружены два неиспользуемых media relationships. Удаляются только ссылки на изображения, которые не используются сохраненным титулом; рисунки отчета и используемые части шаблона сохраняются. Поврежденный/отсутствующий шаблон вызывает явный отказ.

Фактическая верстка проверяется через Microsoft Word16 → PDF, без сохранения изменений в DOCX. Автоматическая структурная проверка не выдается за просмотр каждой страницы. Во время доработки реально просмотрены титул, начало основного текста и страница формул; найденные ошибки темы/двойного PAGE исправлены и закреплены регрессионным тестом. Статусы и контрольные суммы текущего рендера — output/internal_review/render_status.json.

## 6. Формулы DCF

Используй формулы именно из лекции и задания.

### Revenue

Если присутствуют `P_t` и `Q_t`:

```text
Revenue_t = P_t × Q_t
```

Однако если `data.csv` содержит непосредственно `Revenue_Profile` и не содержит отдельных `P_t` и `Q_t`, **НЕ выдумывай** цену и объём.

В таком случае используй `Revenue_Profile` как непосредственно заданный `Revenue_t` и зафиксируй это решение в логе.

### OPEX

По заданию:

```text
OPEX_t =
Сырьё
+ Утилиты
+ Персонал
+ ТОиР
```

Если CSV содержит только агрегированный `OPEX_Profile`, а детализация отсутствует, используй заданное агрегированное значение.

Не создавай фиктивную детализацию затрат.

### Амортизация

Использовать линейный метод.

Срок эксплуатации:

```text
10 лет
```

или значение `project_lifetime_years` из данных, если именно оно используется в текущем сценарии.

При использовании метода Ленга не амортизируй оборотный капитал.

Амортизационная база должна относиться к амортизируемым основным средствам.

Если возникает неоднозначность FCI / TCI / CAPEX — явно опиши принятое решение в Harness Log и итоговом отчёте.

### EBIT

```text
EBIT_t =
Revenue_t
− OPEX_t
− D&A_t
```

### NOPAT

```text
NOPAT_t =
EBIT_t × (1 − tax_rate)
```

Следовать методике задания.

Не вводить самостоятельно сложную модель переноса налоговых убытков на будущие периоды, если этого нет в исходных материалах.

При отрицательном EBIT отдельно проверить математическое поведение налогового щита.

### FCF

```text
FCF_t =
NOPAT_t
+ D&A_t
− CAPEX_t
− ΔNWC_t
```

> **КРИТИЧЕСКИ ВАЖНО:**  
> Не забыть вернуть `D&A` после расчёта `NOPAT`.
>
> Это одна из явно указанных в задании типичных ошибок ИИ.

## 7. Не допускать двойного учёта CAPEX

Проверь архитектуру денежных потоков.

Если первоначальные инвестиции `I0` полностью учитываются в году 0, нельзя второй раз вычитать тот же CAPEX в FCF будущих периодов.

Аналогично нельзя одновременно включить Working Capital в `I0/TCI` и повторно вычесть ту же сумму как `ΔNWC` без экономического основания.

Создай явную схему денежных потоков:

```text
Год 0
→ первоначальные инвестиции

Годы 1…N
→ операционные денежные потоки
```

Если дополнительные CAPEX отсутствуют в исходных данных:

```text
CAPEX_t = 0 для t = 1…N
```

Если отдельная динамика NWC отсутствует, не выдумывай ежегодный `ΔNWC`.

Все допущения записать в лог.

## 8. CAPEX по методу Ленга

Реализовать отдельный метод:

```python
calculate_lang_capex()
```

Формула:

```text
FCI = f_L × ΣE_i
```

где:

- `E_i` — поставочная стоимость i-го аппарата;
- `f_L` — коэффициент Ленга.

Затем:

```text
TCI = FCI / (1 − WC)
```

Типовые коэффициенты из лекции:

- твёрдые вещества: около `3.10`;
- комбинированный solid-fluid процесс: около `3.63`;
- жидкостный/газовый процесс: около `4.74`.

Объект задания:

```text
R&D-центр синтеза твердотельных электролитов,
TRL 3,
комбинированный процесс
```

Используй значение из `data.csv`, если оно задано.

Проверь его соответствие методологии лекции и отрази обоснование в отчёте.

Не подменяй коэффициент другим без объяснения.

## 11. PI


При этом перед реализацией проверь, есть ли явная формула PI в приложенной лекции.

## 12. DPP / DPBP

Использовать дисконтированный срок окупаемости.

Для каждого года рассчитать:

```text
Discounted_CF_t =
CF_t / (1 + WACC)^t
```

далее накопленный дисконтированный поток.

Определить первый период, в котором накопленный дисконтированный поток становится `>= 0`.

Если проект не окупается за расчётный горизонт, результат должен быть:

```text
Не окупается в пределах горизонта модели
```

а не фиктивное число.

При необходимости определить дробную часть года через интерполяцию, но только если это не противоречит методике задания.

Если используется интерполяция — явно указать это.

## 20. Монте-Карло

Реализовать `1000` итераций.

Не выполнять симуляцию вручную или средствами ИИ.

Неопределённости:

```text
CAPEX:
±30%

Revenue:
±20%
```

Перед моделированием явно определить статистическую интерпретацию этих процентов.

Поскольку задание допускает нормальное либо логнормальное распределение, выбери и обоснуй вариант.

Предпочтительно не допускать физически бессмысленный отрицательный CAPEX.

Практически можно моделировать случайный мультипликатор CAPEX и Revenue относительно базового сценария.

Например:

```text
CAPEX_scenario =
CAPEX_base × multiplier_capex

Revenue_t_scenario =
Revenue_t_base × multiplier_revenue
```

Для нулевой выручки базового периода должно сохраняться:

```text
0 × multiplier = 0
```

Если используешь логнормальное распределение, корректно преобразуй требуемое среднее и коэффициент вариации в параметры логнормального распределения.

Не принимать параметры функции random/lognormal «на глаз».

Обеспечить воспроизводимость:

- зафиксировать `random seed`.

Для каждой итерации пересчитать NPV.

Сформировать:

1. массив из 1000 NPV;
2. среднее NPV;
3. медиану;
4. стандартное отклонение;
5. минимум;
6. максимум;
7. квантили;
8. `P(NPV < 0)`.

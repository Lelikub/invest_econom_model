# DCF/CAPEX Pipeline Design

## Цель

Создать в каталоге `1/app/` воспроизводимое Python-приложение, которое одной командой читает исходный `1/data/data.csv`, выполняет DCF-расчет и факторную оценку CAPEX методом Ленга, строит независимую Excel Ground Truth модель, сверяет ее с Python, запускает тестовые сценарии, Монте-Карло и стресс-тест, а затем формирует графики, журналы и итоговый Word-отчет на русском языке.

## Источники и приоритет данных

Методология и формулы берутся из:

1. `1/data/Задание_к_практическому_занятию_1_ФИП.pdf`;
2. `1/data/Лекция 1 ФИП слайды.pdf`.

Фактические машинные входы текущего сценария берутся из `1/data/data.csv`. Исходные файлы не изменяются.

При первичном аудите выявлены два расхождения между заданием и CSV:

- WACC: в задании `10%`, в CSV `12%`;
- доля оборотного капитала: в задании `12%`, в CSV `15%`.

Оба значения и их источники отражаются в runtime log, Harness Log, листе проверки исходных данных и Word-отчете. Для Python и Excel используются одинаковые значения CSV. Коэффициент Ленга `3,63` из CSV соответствует указанному в лекции комбинированному solid-fluid процессу.

## Компоненты

### Модель данных и загрузка

`ProjectData` — типизированный dataclass с перечнем оборудования, параметрами, профилями Revenue и OPEX. Загрузчик:

- проверяет колонки `Category`, `Item`, `Value`;
- отклоняет пустые, нечисловые и дублирующиеся значения;
- проверяет обязательные параметры и допустимые диапазоны;
- проверяет годы `Year_1 ... Year_N` и совпадение горизонта Revenue/OPEX;
- сохраняет диагностические результаты и расхождения с PDF;
- не создает отсутствующую детализацию Revenue или OPEX.

### Финансовая модель

`FinancialModel` принимает только `ProjectData` либо явно созданный сценарий на его основе. Базовые правила:

- стоимость оборудования — сумма строк `Equipment_Cost`;
- `FCI = lang_factor × equipment_cost`;
- `TCI = FCI / (1 - working_capital_share)`;
- первоначальные инвестиции года 0: `I0 = TCI`;
- амортизируемая база: `FCI`, без оборотного капитала;
- линейная амортизация: `FCI / project_lifetime_years` ежегодно;
- Revenue и OPEX берутся непосредственно из агрегированных CSV-профилей;
- `EBIT = Revenue - OPEX - D&A`;
- `NOPAT = EBIT × (1 - tax_rate)`, включая отрицательный EBIT согласно формуле задания;
- `FCF = NOPAT + D&A` для годов 1...N, поскольку дополнительный CAPEX и ежегодная динамика NWC не заданы;
- год 0 содержит единственный поток `-TCI`, что исключает двойной учет CAPEX/WC;
- терминальная стоимость отсутствует;
- `NPV = -I0 + Σ FCF_t/(1+WACC)^t`;
- IRR ищется численно только при корректной структуре знаков потока; неоднозначные и несуществующие решения возвращаются как статус, а не как фиктивное число;
- PI рассчитывается по явно обозначенному стандартному определению `PV будущих FCF / I0`, поскольку отдельной формулы PI в лекции нет; при `I0 = 0` возвращается понятный неопределенный статус;
- DPBP определяется по накопленному дисконтированному потоку с линейной интерполяцией внутри первого окупающего года; если окупаемости нет, возвращается соответствующий статус.

Денежная единица исходных данных сохраняется как условная единица одного масштаба; приложение не присваивает ей валюту без источника.

### Excel Ground Truth

`ExcelGroundTruthBuilder` создает `1/app/output/DCF_Ground_Truth.xlsx` средствами `openpyxl`. Видимые листы и заголовки — на русском языке:

1. `Исходные данные`;
2. `Оборудование и CAPEX`;
3. `DCF-модель`;
4. `Ключевые показатели`;
5. `Сравнение Python Excel`;
6. `Граничные тесты`;
7. `Монте-Карло`;
8. `Стресс-тест`;
9. `Проверка исходных данных`.

Расчетные ячейки содержат формулы со ссылками на исходные параметры, а не выгруженные Python-результаты. После записи книга открывается установленным Microsoft Excel через COM, принудительно пересчитывается и сохраняется. Затем cached values читаются обратно отдельным проходом. Если COM-пересчет не выполнен, pipeline завершается ошибкой и фиксирует техническую причину; пустые cached values не считаются результатом.

Excel самостоятельно рассчитывает годовые строки DCF, FCI, TCI, NPV, IRR, PI и DPBP. Для метрик со статусом применяются безопасные формулы и пояснения. Книга получает единое оформление, форматы процентов и денежных величин, закрепленные заголовки, ширины колонок и условное форматирование сверки.

### Сверка Python и Excel

`MetricsComparator` сравнивает FCI, TCI, амортизацию, EBIT, NOPAT, FCF по годам, NPV, IRR, PI и числовой DPBP. Для каждого показателя сохраняются значения Python/Excel, абсолютное и относительное отклонения и статус. При нулевом Excel-значении используется отдельное абсолютное сравнение.

Порог успеха для ключевых числовых метрик строгий: относительное отклонение должно быть меньше `0,01%`. Любое несоответствие либо несовпадение статусов завершает pipeline ошибкой до формирования итогового Word-отчета.

### Граничные сценарии

Сценарии создаются в памяти и не изменяют CSV:

- CAPEX = 0: проверяются NPV, IRR, неопределенный PI, DPBP и отсутствие деления на ноль;
- WACC = 0%: NPV должен совпадать с недисконтированной суммой всех потоков;
- отрицательная экономика: отрицательная Revenue и/или OPEX выше Revenue должны сохранять формулы EBIT, NOPAT и налогового щита.

Результат каждого сценария включает входы, ожидаемое свойство, фактическое значение, `PASS/FAIL` и комментарий. Помимо этих сценариев, pytest покрывает загрузчик, CAPEX Ленга, DCF-метрики, статусы IRR/PI, сверку Excel и сквозной pipeline.

### Монте-Карло и графики

Выполняются ровно 1000 итераций с фиксированным seed. Для CAPEX и Revenue применяются независимые логнормальные мультипликаторы со средним 1,0 и коэффициентами вариации 30% и 20%. Параметры логнормального распределения вычисляются из требуемых среднего и коэффициента вариации, что исключает отрицательный CAPEX и Revenue-мультипликатор. Нулевая базовая Revenue остается нулевой.

В каждой итерации пересчитывается NPV. Сохраняются среднее, медиана, стандартное отклонение, минимум, максимум, квантили 5%, 25%, 50%, 75%, 95% и `P(NPV < 0)`. Создаются:

- `1/app/output/histogram_npv.png`;
- `1/app/output/s_curve_npv.png` с интерпретацией `P(NPV ≤ x)`.

Все подписи графиков — на русском языке.

### Стресс-тест

Стресс-сценарий использует `TCI/FCI × 2` через удвоение базового CAPEX и `Revenue × 0,7`, сохраняя прочие предпосылки. Сравниваются NPV, IRR, PI, DPBP, FCI, TCI и годовые FCF; таблица содержит базовое значение, стресс-значение, абсолютное и относительное изменения.

### Логи и отчет

`1/app/logs/execution.log` содержит технический журнал Python `logging` с этапами, предупреждениями, исключениями и итогами проверок.

`1/app/output/Harness_Log.xlsx` содержит только реально выявленные проблемы: обнаруженные расхождения PDF/CSV, методологические допущения PI и DPBP, результаты проверки двойного учета, проблемы запуска/пересчета Excel и исправления, подтвержденные повторным запуском.

`1/app/output/Итоговый_отчет_ФИП.docx` создается только после успешной сверки и тестов. Он содержит 3–4 страницы основного текста на русском языке: цель, входы и расхождения, методику, CAPEX Ленга, базовые метрики, сверку Excel/Python, граничные тесты, Монте-Карло с двумя графиками, стресс-тест, краткую выжимку Harness Log и вывод, программно сформированный из рассчитанных результатов.

## Поток выполнения

```text
CSV и контрольные значения PDF
→ валидация и аудит расхождений
→ ProjectData
→ базовая Python-модель
→ Excel с формулами
→ пересчет Excel через COM
→ чтение cached values
→ сравнение Python ↔ Excel
→ граничные тесты
→ Монте-Карло
→ стресс-тест
→ графики и Harness Log
→ Word-отчет
```

При ошибке этап записывает контекст в runtime log и прекращает зависимые шаги. Word-отчет не создается из частичных либо непроверенных результатов.

## Зависимости и запуск

Приложение ориентировано на доступный Python 3.10+ и Windows с установленным Microsoft Excel. Основные зависимости: `numpy`, `openpyxl`, `pywin32`, `matplotlib`, `python-docx`, `pytest`.

После установки зависимостей полный запуск выполняется из корня репозитория:

```powershell
python 1/app/main.py
```

Тесты:

```powershell
python -m pytest 1/app/tests -v
```

README фиксирует точную команду для найденного в среде интерпретатора, если системный alias `python` недоступен.

## Критерии готовности

- Основная реализация находится в `1/app/` и запускается одной командой.
- Исходный CSV читается программно и не изменяется.
- Все обязательные финансовые показатели получены кодом.
- XLSX содержит реальные формулы, пересчитан Excel и успешно прочитан обратно.
- Ключевые Python/Excel результаты совпадают с отклонением `<0,01%`.
- Все pytest и три обязательных граничных сценария проходят.
- Монте-Карло содержит 1000 воспроизводимых расчетов и `P(NPV < 0)`.
- Стресс-тест и оба русскоязычных графика сформированы.
- Созданы runtime log, Harness Log, Excel, сравнительные результаты и Word-отчет.
- Все артефакты открываются без ошибок и содержат согласованные итоговые значения.

# Перенос реализации проекта в каталог `1`

## Цель

Собрать все содержательные материалы задания в одном каталоге `1/`: исходные данные, формулировку задания, приложение, документацию и пользовательский оформленный отчет. Корень репозитория остается только для служебных файлов Git и локальных рабочих копий.

## Целевая структура

```text
1/
├── app/
│   ├── src/
│   ├── tests/
│   ├── output/       # генерируемые файлы, не версионируются
│   ├── logs/         # журналы выполнения, не версионируются
│   ├── main.py
│   ├── run_tests.py
│   ├── requirements.txt
│   └── README.md
├── data/
├── task/
├── docs/
│   └── superpowers/
│       ├── plans/
│       └── specs/
└── reports/
    └── Итоговый_отчет_ФИП_оформленный.docx
```

В корне репозитория остаются `.git/`, `.gitignore` и локальный каталог `.worktrees/`. Каталог `.worktrees/` является отдельной служебной рабочей копией Git и не входит в состав проекта в ветке `main`.

## Перенос и пути выполнения

- Текущий `app/` переносится в `1/app/` с сохранением истории Git.
- Текущий `docs/` переносится в `1/docs/` с сохранением истории Git.
- Импорты приложения меняются с `app.src...` на `src...`, чтобы приложение запускалось непосредственно из `1/app/main.py` без превращения каталога `1` в Python-пакет.
- Корень задания для приложения вычисляется как родитель `1/app`, то есть `1/`.
- Входной CSV по умолчанию разрешается как `1/data/data.csv`.
- Генерируемые результаты записываются в `1/app/output/`, журнал — в `1/app/logs/execution.log`.
- Команды запуска становятся `python 1/app/main.py` и `python 1/app/run_tests.py`.
- Тесты и документация обновляются под новые пути.

## Сохранение пользовательского отчета

Файл `Итоговый_отчет_ФИП_оформленный.docx`, найденный в текущем `app/output/`, переносится в `1/reports/` и добавляется в Git. Он хранится отдельно от автоматически формируемого `1/app/output/Итоговый_отчет_ФИП.docx`, поэтому повторный запуск конвейера его не перезапишет и правила игнорирования результатов его не скроют.

Перед переносом сверяется размер и SHA-256 исходного файла; после переноса проверяется совпадение этих значений.

## Правила игнорирования

`.gitignore` обновляется для новых путей:

- `1/app/.python-packages/`;
- `1/app/.test-tmp*/`;
- `1/app/output/`;
- `1/app/logs/`.

Каталог `1/reports/` не игнорируется. Оформленный отчет добавляется в репозиторий явно.

## Проверка результата

После переноса необходимо подтвердить:

1. В корне больше нет содержательных каталогов `app/` и `docs/`.
2. Пользовательский отчет находится в `1/reports/`, отслеживается Git и совпадает с исходным файлом по размеру и SHA-256.
3. Полный набор тестов запускается из новой структуры и проходит без ошибок.
4. Производственный запуск из `1/app/main.py` создает все ожидаемые артефакты внутри `1/app/output/` и журнал внутри `1/app/logs/`.
5. Исходный `1/data/data.csv` не изменен.
6. Рабочее дерево `main` не содержит незакоммиченных отслеживаемых изменений после фиксации результата.

## Границы изменения

Расчетные формулы, исходные данные и содержание автоматически создаваемых отчетов не меняются. Существующая отдельная рабочая копия `.worktrees/dcf-capex-pipeline` сохраняется как резервная и не включается в коммиты `main`.
